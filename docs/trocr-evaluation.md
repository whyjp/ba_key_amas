# TrOCR 검증과 적용 가치

2026-11-25. Rust 이식(`crates/ocr/src/trocr.rs`)을 같은 160장 이름판(`scanner/fixtures/plates`)에서 현재 경로와 비교했다.
실행: `BAOCR_TROCR=<encoder.onnx와 decoder.onnx가 있는 폴더> ba-key-AMAS --eval-plates scanner/fixtures/plates`.
TrOCR은 사전 전체(280개 이름)를 후보로 점수를 매겨(토큰당 평균 로그확률) 가장 높은 이름을 고른다. 현재 경로는 PP-OCR의
이름판 읽기(`read_plate`: 재판독 투표 포함)에 사전 보정(`best_name`)을 붙인 것이다. 흐림은 이름판을 줄였다가 다시 키운 것이다.

| 조건 | PP-OCR + 사전 | TrOCR (사전 전체) | 둘 중 하나라도 맞음 |
|---|---|---|---|
| 원본 | 159/160 | 160/160 | 160/160 |
| 흐림 0.7 | 157/160 | 160/160 | 160/160 |
| 흐림 0.5 | 103/160 | 159/160 | 159/160 |
| 흐림 0.4 | 32/160 | 149/160 | 150/160 |
| 시간(CPU, 장당) | 약 82 ms | 약 815 ms | |

- 원본에서 PP-OCR이 틀리는 한 장은 `아야네`다(사전 보정 뒤에도 빈 값). TrOCR은 맞혔다.
- 흐림에서 격차가 크다. 게임 창이 작아서 프레임을 키워 쓰거나 해상도가 낮은 환경이 여기에 해당한다.
- 한계: 정답 라벨은 이전 엔진의 판독을 사전에 맞춰 자동으로 붙인 것이다(일부만 눈으로 확인). 같은 이름판에서 측정했고 다른 계정과 해상도는 아직 보지 못했다.

## 판단

- **지금의 화면(원본 해상도)에서 얻는 정확도는 160장 중 1장이다.** 이 이름판은 PP-OCR과 사전 보정이 이미 99.4%다.
- **모두에게 켜기에는 비용이 크다.** 장당 0.8초(106명이면 약 85초)와 모델 109 MB(fp16w)가 든다. 압축한 릴리스 크기가 48 MB에서 크게 늘어난다.
- **적용 가치가 있는 형태는 "사전 보정이 비거나 모호할 때만 TrOCR".** 원본에서는 이름판의 1~2%만 해당해서 시간 비용이 거의 없고, 흐린 환경에서는 실패하는 판독을 TrOCR이 되살린다(0.5에서 PP-OCR이 틀린 57장 중 56장). 후보를 PP-OCR의 근접 이름 8~24개로 줄이면 장당 130~170 ms다.
- **라이브 빠른 편성 이름 읽기에는 쓰지 않는다.** 카드 12장에 약 1.5초가 들고, 썸네일 보기는 초상화로 이미 읽는다.
- **결정이 필요한 것.** 모델을 릴리스에 넣을지, 선택 다운로드로 둘지. 선택 다운로드면 해당하는 사용자만 받는다.
