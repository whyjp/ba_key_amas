Blue Archive 애드온 아키텍처

게임 화면을 읽고 카드와 아이콘으로 답하는 Rust 상주 Windows 프로그램이다. 원본 문서는 docs/ARCHITECTURE.md와 docs/adr/다.

1. 실행 흐름

루프는 전투 중이거나 화면을 읽은 뒤 화면이 멈춰 있으면 느리게 폴링한다. 오버레이 스레드는 변경이 있을 때 깨어난다.

2. 크레이트 의존 그래프 (scripts/gen_arch.py가 cargo metadata에서 생성)

3. 정적 데이터와 동적 데이터

데이터종류출처
화면, 임무, 스테이지, 레이드 보스, 난이도, 모드동적OCR과 픽셀(조회 키만)
편성 구성원과 슬롯동적닫힌 집합 이름 읽기
적 방어 타입과 공격 타입 비중, 레벨, 지형정적wiki.db
학생 타입, 적응, 역할, 타입 상성표정적wiki.db
도킹 위치, 접기 상태, 스위치사용자 상태overlay.json

규칙: 화면은 조회 키를 제공하고, 데이터베이스는 정보를 제공한다(ADR 0005).

4. OCR 파이프라인

CPU나 DirectML(--features directml)에서 돈다. 픽스처에서 2.7배 빠르고 결과 텍스트는 같다. ADR 0002 참고.

5. 스레드와 창

스레드 또는 창하는 일
메인 루프캡처, 읽기, 관찰, 표시, 스캔 실행
오버레이 워커레이어드 창 네 개(카드는 상호작용형, 게임 내 카드, 아이콘, 툴팁은 클릭 통과, 모두 캡처에서 제외), 변경이 있을 때 그린다
트레이종료 메뉴가 있는 알림 아이콘, 자체 숨은 창에서 동작
입력 차단스캔 중에만 동작: 저수준 훅, 주입된 이벤트는 통과, ESC로 중단
입력 힌트(꺼짐)더 빠른 인식을 위한 통과형 마우스 타임스탬프

6. 입력 정책

  • 수동 관찰 코드는 읽기 전용 핸들을 받는다. 입력은 Exclusive에만 있고, 플레이어가 스캔을 시작할 때 얻는다.
  • 안전장치는 한 경계에 둔다. 점이 모니터 안에 있는지, 창 레이아웃이 그대로인지, 점 아래에 대상 창이 있는지 검사한다. 부분 입력은 effect_unknown으로 처리하고 재시도하지 않는다.
  • 입력 호출은 모두 내용 없이 기록한다. 스캔 중에는 플레이어 자신의 입력이 막히고, 하드웨어 ESC가 제어권을 돌려준다.

7. 결정 기록

0001 애드온 셸 확정상주 애드온, 수동 관찰 우선, 스캔은 직접 시작. 0002 OCR 스택 확정프로세스 내 ONNX Runtime의 PP-OCR, DirectML은 선택, 이름은 닫힌 집합 읽기. 0003 네이티브 데스크톱 제어 확정HCU 헬퍼 대신 프로세스 내 Win32. 0004 입력 정책 확정입력은 스캔에만, 안전장치를 거치고, 관찰만 하며 가로채지 않는다. 0005 정적 DB, 동적 화면 확정정보는 데이터베이스에서, 조회 키는 화면에서. 0006 적 가중 확정HP로 가중한 방어 타입과 공격 타입 비중(DB v4). 0007 오버레이 창 확정레이어드 창, 변경 캐시, 북마크 카드. 0008 레이드 모델링 확정난이도 행, 시즌, 레이드 화면. 0009 빌드 제한 확정RAM과 디스크를 제한하는 설정.
